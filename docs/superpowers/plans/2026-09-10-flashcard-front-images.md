# Flashcard Front Images Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a flashcard creator attach one optional image to the front (question) side of each card; the image is uploaded from the device to Vercel Blob and shown on the front in both flip mode and quiz mode.

**Architecture:** Additive to the existing Next.js 14 + Prisma app. `Flashcard` gains a nullable `imageUrl` column. A new `POST /api/upload` route stores an uploaded image in Vercel Blob and returns its public URL; a new client component `ImageUploadField` drives that upload and a thumbnail/remove UI. The flashcard edit page renders that component under each card's front input; the flashcard play page renders an `<img>` above the front text. Text on both card sides stays required. The sort game, matching game, and passcode gate are untouched.

**Tech Stack:** Next.js 14 (App Router, TypeScript), Prisma, SQLite (dev) / Turso (prod), Vitest (node environment — pure-module unit tests only, no route/component test harness in this repo), Vercel. One new dependency: `@vercel/blob`.

**Spec:** `docs/superpowers/specs/2026-09-10-flashcard-front-images-design.md`

## Global Constraints

- Passcode gate stays as-is: `middleware.ts` already blocks unauthenticated requests to everything except `api/login`, so `POST /api/upload` is protected with no middleware change. Do not add auth logic inside the upload handler.
- Prisma is the only DB access layer — no raw SQL in app code.
- Flashcard-game logic stays in its own pure module `lib/flashcard-game.ts` — no shared logic with `lib/sort-game.ts` or `lib/matching-game.ts`.
- `front` and `back` stay **required and non-blank** on every card (client validation before any API call, and server validation on `PUT`). An image alone never makes a card valid.
- `imageUrl` is **nullable**. An `imageUrl` sent as an empty or whitespace-only string MUST be stored as `null`.
- Image files: client rejects anything over **4 MB** (`MAX_IMAGE_BYTES = 4 * 1024 * 1024`) before uploading; Vercel caps a route body at 4.5 MB.
- Only `image/*` MIME types are accepted by the upload route.
- If `process.env.BLOB_READ_WRITE_TOKEN` is unset, `POST /api/upload` returns HTTP **503** with body `{ "error": "storage not configured" }` — never a crash.
- Images render with a plain `<img loading="lazy">` — **not** Next.js `<Image>`. No `next.config` `images` changes.
- All rendered images use `object-fit: contain` and `max-width: 100%`.
- Migration is additive: one new Prisma migration adding a nullable column, applied to the **local SQLite dev DB only** via `npx prisma migrate dev`. The production Turso DB is migrated separately **by the user** via `node scripts/apply-turso-migrations.mjs`; this plan does not run that script.
- Reuse existing design-system classes (`.btn`, `.btn-outline`, `.btn-sm`, `.text-input`, `.error-banner`) and the existing `AlertDialog` component for edit-page validation messages — do not use native `alert`.
- Existing matching-game and sort-game routes, pages, data, and tests must not change behavior.

```typescript
export const MAX_IMAGE_BYTES = 4 * 1024 * 1024;

export function validateImageFile(file: { type: string; size: number }): string | null {
  if (!file.type.startsWith("image/")) return "ไฟล์ต้องเป็นรูปภาพ";
  if (file.size > MAX_IMAGE_BYTES) return "ไฟล์ใหญ่เกิน 4MB";
  return null;
}

export function normalizeImageUrl(raw: unknown): string | null {
  if (typeof raw !== "string") return null;
  const trimmed = raw.trim();
  return trimmed === "" ? null : trimmed;
}

export function sanitizeFilename(name: string): string {
  const cleaned = name.replace(/[^A-Za-z0-9._-]/g, "_");
  return cleaned.replace(/^_+$/, "") === "" ? "image" : cleaned;
}
```

## Task 4: `POST /api/upload` route

**Files:**
- Create: `app/api/upload/route.ts`
- Modify: `package.json`, `package-lock.json` (adding `@vercel/blob`)

**Interfaces:**
- Consumes: `validateImageFile`, `sanitizeFilename` from `lib/upload-validation` (Task 2); `put` from `@vercel/blob`.
- Produces: `POST /api/upload` — accepts `multipart/form-data` with a `file` field; responses:
  - `201 { url: string }` on success
  - `400 { error: string }` when the file is missing, not an image, or over 4 MB
  - `503 { error: "storage not configured" }` when `BLOB_READ_WRITE_TOKEN` is unset

- [ ] **Step 1: Install the dependency**

Expected: `@vercel/blob` appears in `package.json` `dependencies` and `package-lock.json` updates.

- [ ] **Step 2: Write the route**

Create `app/api/upload/route.ts`:

```typescript
import { randomUUID } from "crypto";
import { NextRequest, NextResponse } from "next/server";
import { put } from "@vercel/blob";
import { validateImageFile, sanitizeFilename } from "@/lib/upload-validation";

export async function POST(req: NextRequest) {
  if (!process.env.BLOB_READ_WRITE_TOKEN) {
    return NextResponse.json({ error: "storage not configured" }, { status: 503 });
  }

  const form = await req.formData();
  const file = form.get("file");

  if (!(file instanceof File)) {
    return NextResponse.json({ error: "file is required" }, { status: 400 });
  }

  const validationError = validateImageFile(file);
  if (validationError) {
    return NextResponse.json({ error: validationError }, { status: 400 });
  }

  const key = `uploads/${randomUUID()}-${sanitizeFilename(file.name)}`;
  const blob = await put(key, file, {
    access: "public",
    contentType: file.type,
    addRandomSuffix: false,
  });

  return NextResponse.json({ url: blob.url }, { status: 201 });
}
```

- [ ] **Step 1: Write the component**

Create `components/ImageUploadField.tsx`:

```tsx
"use client";

import { useRef, useState } from "react";
import { validateImageFile } from "@/lib/upload-validation";
import styles from "./ImageUploadField.module.css";

type Props = {
  value: string | null;
  onChange: (url: string | null) => void;
  label?: string;
};

export function ImageUploadField({ value, onChange, label = "รูปภาพ" }: Props) {
  const inputRef = useRef<HTMLInputElement>(null);
  const [uploading, setUploading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  async function handleFile(file: File) {
    const validationError = validateImageFile(file);
    if (validationError) {
      setError(validationError);
      return;
    }
    setError(null);
    setUploading(true);
    try {
      const form = new FormData();
      form.append("file", file);
      const res = await fetch("/api/upload", { method: "POST", body: form });
      const body = await res.json().catch(() => ({}));
      if (!res.ok) {
        throw new Error(body.error || `อัปโหลดไม่สำเร็จ (${res.status})`);
      }
      onChange(body.url as string);
    } catch (err) {
      setError(err instanceof Error ? err.message : "อัปโหลดไม่สำเร็จ");
    } finally {
      setUploading(false);
      if (inputRef.current) inputRef.current.value = "";
    }
  }

  return (
    <div className={styles.wrap}>
      <input
        ref={inputRef}
        type="file"
        accept="image/*"
        hidden
        onChange={(e) => {
          const file = e.target.files?.[0];
          if (file) handleFile(file);
        }}
      />
      {value ? (
        <div className={styles.preview}>
          {/* eslint-disable-next-line @next/next/no-img-element */}
          <img src={value} alt={label} className={styles.thumb} />
          <button
            type="button"
            className="btn btn-outline btn-sm"
            onClick={() => onChange(null)}
            disabled={uploading}
          >
            ✕ ลบรูป
          </button>
        </div>
      ) : (
        <button
          type="button"
          className="btn btn-outline btn-sm"
          onClick={() => inputRef.current?.click()}
          disabled={uploading}
        >
          {uploading ? "กำลังอัปโหลด..." : "+ เพิ่มรูป"}
        </button>
      )}
      {error && <p className={styles.error}>{error}</p>}
    </div>
  );
}
```
